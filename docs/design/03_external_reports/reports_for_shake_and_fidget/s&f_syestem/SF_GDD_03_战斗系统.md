## 1. 系统概述与设计目标

🅰️ **A级**（官方帮助中心）

### 1.1 系统定位

SF Game 的战斗系统是完全**自动化、无玩家输入**的战斗仿真器：
- 玩家**不直接操控战斗**，所有战斗结果由双方数值和随机数决定
- 战斗在游戏服务器端执行，客户端仅展示回放动画
- 战斗系统的作用是**将装备/属性投入转化为可量化的战斗胜率**

### 1.2 战斗设计哲学

| 设计原则 | 具体体现 |
|---------|---------|
| **Auto-Battle** | 战斗全自动，玩家只需优化装备和属性 |
| **回合制** | 双方轮流攻击，每回合一次攻击（部分职业除外）|
| **确定性偏低** | 伤害随机范围（武器Min-Max），暴击概率，保持战斗趣味性 |
| **职业差异化** | 11个职业各有独特机制（格挡/闪避/双持/复活等），形成策略深度 |
| **反平局机制** | 怒气系统确保战斗必然结束 |

### 1.3 战斗适用场景

| 场景 | 触发方式 | 双方类型 |
|------|---------|---------|
| 竞技场（Arena）| 主动发起 | 玩家 vs 玩家镜像 |
| 地下城（Dungeon）| 进入副本 | 玩家 vs NPC敌人 |
| 堡垒攻防 | 驻军/攻城 | 玩家部队 vs 玩家部队 |
| 魔法镜（Mirror）| 自动代理 | 玩家镜像 vs 玩家镜像 |
| 任务剧情战斗 | 特定任务触发 | 玩家 vs NPC |

## 2. 战斗触发场景

🅰️ **A级**（官方帮助中心）

### 2.1 竞技场战斗

- 从**名人堂**（Hall of Fame）中随机取3名玩家作为对手候选
- 玩家选择对手后立即进行一次战斗（即时结算）
- 每日有**限制次数**（基础约10次，可通过坐骑等扩展）
- 胜利获得荣誉值（Honor）提升排名，失败扣除荣誉值

### 2.2 地下城战斗

- 地下城由一系列NPC敌人组成，**依次顺序挑战**
- 战斗结果即时判定，失败则停在对应NPC（不需重新从头开始）
- 每日可重置（消耗地下城钥匙）
- Boss级敌人通常有更高等级，是地下城的主要挑战

### 2.3 战斗快速结算

🅱️ **B级**（社区总结）

- 战斗实际为"服务器侧即时结算"，客户端展示动画仅为视觉呈现
- 玩家无法在战斗过程中干预

## 3. 生命值（HP）计算

🅲 **C级**（sf-tools `js/sim/base.js` 逆向）

### 3.1 核心公式

```
最终HP = ceil(
  体力总值(CON_Total)
  × 职业生命倍率(ClassLifeMultiplier)
  × (等级 + 1)
  × (1 + 零食体力加成 / 100)
  × (1 + 生命药水加成 / 100)
  × (1 + 个人副本生命加成 / 100)
  × (1 + 生命符文加成 / 100)
  × 其他自定义生命倍率
)
```

> `ceil` = 向上取整（Math.ceil）

### 3.2 职业生命倍率（ClassLifeMultiplier）

🅰️ **A级**（官方帮助中心 + sfporadnik.pl）

| 职业 | 生命倍率 | 定位说明 |
|------|---------|---------|
| **圣骑士 Paladin** | ×6 | 血量最高，坦克首选 |
| **战士 Warrior** | ×5 | 高血量近战 |
| **战斗法师 Battle Mage** | ×5 | 法系中血量最厚 |
| **德鲁伊 Druid** | ×5 | 变形态后血量充裕 |
| **游侠 Scout** | ×4 | 中等血量 |
| **刺客 Assassin** | ×4 | 中等血量，靠双持补偿 |
| **恶魔猎手 Demon Hunter** | ×4 | 中等血量，有复活兜底 |
| **死灵法师 Necromancer** | ×4 | 中等血量 |
| **狂战士 Berserker** | ×4 | 中等血量，护甲减半 |
| **法师 Mage** | ×2 | 脆皮，靠绕甲弥补 |
| **吟游诗人 Bard** | ×2 | 脆皮，靠旋律增伤 |

### 3.3 HP 数值示例（体力=1000，等级=30）

| 职业 | 计算结果 |
|------|---------|
| 圣骑士（×6）| ceil(1000 × 6 × 31) = **186,000 HP** |
| 战士（×5）| ceil(1000 × 5 × 31) = **155,000 HP** |
| 法师（×2）| ceil(1000 × 2 × 31) = **62,000 HP** |

> 🗒️ 体力1000是便于计算的假设值，实际30级玩家体力约为300-600范围。

### 3.4 设计意图

🅳 **D级**（推测）

- 圣骑士 × 6 vs 法师 × 2 形成 **3倍血量差**，与法师"绕甲"能力形成平衡
- 等级+1 因子使 HP **线性跟随等级增长**，确保数值缩放稳定

## 4. 护甲减伤系统

🅲 **C级**（sf-tools `js/sim/base.js`）

### 4.1 护甲减伤公式

```
减伤百分比(ArmorReduction%) = 
  min(
    职业最大减伤上限(ClassMaxReduction),
    护甲值(ArmorValue) / 攻击方等级(AttackerLevel)
  )
```

等效说明：
- **护甲效率 = 护甲值 / 攻击方等级**
- 实际减伤 = min(职业上限, 护甲效率)
- 攻击方等级越高，你的护甲减伤越低（高等级对低等级的"等级碾压"）

### 4.2 各职业护甲减伤上限

🅰️ **A级**（官方帮助中心 + sfporadnik.pl）

| 职业 | 最大减伤上限 | 备注 |
|------|------------|------|
| **战士 Warrior** | 50% | 标准重甲 |
| **战斗法师 Battle Mage** | 50% | 护甲系数500%，可堆超高护甲 |
| **恶魔猎手 Demon Hunter** | 50% | 与DH复活联动形成强韧性 |
| **狂战士 Berserker** | 50%（实际护甲减半）| 护甲值降低50%，有效上限约25% |
| **圣骑士 Paladin（防御姿态）** | 45% | 进攻姿态降为20% |
| **游侠 Scout** | 25% | 配合闪避 |
| **刺客 Assassin** | 25% | 配合双持 |
| **德鲁伊 Druid（普通/鹰形）** | 25% | 熊形态提升至50% |
| **死灵法师 Necromancer** | 10% | 极低护甲，靠召唤物弥补 |
| **法师 Mage** | 10% | 极低护甲，但攻击绕甲 |
| **吟游诗人 Bard** | 10% | 极低护甲 |

### 4.3 特殊护甲规则

🅰️ **A级**（官方帮助中心）

| 职业 | 特殊规则 |
|------|---------|
| **法师 Mage** | 攻击时**完全绕过目标护甲**（BypassDamageReduction = true） |
| **战斗法师 Battle Mage** | 奥术彗星（Arcane Comet）同样绕过目标护甲 |
| **德鲁伊（熊形态）** | 减伤上限临时提升至 50% |
| **狂战士 Berserker** | 护甲值乘以 0.5（减半），连击时实际减伤约 12.5~25% |

### 4.4 护甲对目标等级的动态关系

🅲 **C级**（sf-tools 分析）

```javascript
// 示例：攻击方等级对护甲减伤的影响
// 假设防御方护甲值 = 1500，最大减伤上限 = 50%

攻击方Lv10: 1500/10 = 150% → 受上限约束 → 实际减伤 50%
攻击方Lv30: 1500/30 = 50%  → 恰好触达上限  → 实际减伤 50%
攻击方Lv50: 1500/50 = 30%  → 低于上限    → 实际减伤 30%
攻击方Lv100:1500/100 = 15% → 护甲被"等级碾压" → 实际减伤 15%
```

> 🗒️ 结论：**堆护甲的有效期与等级差强相关**。面对高等级对手，必须同步提升护甲数值，否则减伤会大幅下降。

## 5. 伤害计算系统

🅲 **C级**（sf-tools `js/sim/base.js` 伤害函数逆向）

### 5.1 完整伤害计算流程

```
实际伤害 = 武器基础伤害值（随机取 MinDmg ~ MaxDmg 区间）
         × 职业伤害系数（ClassDmgFactor）
         × 属性差加成因子（AttrDiffFactor）
         × (1 - 目标护甲减伤%)
         × 暴击倍率（如触发暴击）
         × 怒气倍率（RageMultiplier）
         × (1 + 零食伤害加成 / 100)
         × (1 + 队伍副本伤害加成 / 100)
         × 符文修正因子（RuneFactor）
```

### 5.2 属性差加成因子（核心公式）

🅲 **C级**（sf-tools `base.js`，最关键的伤害公式）

```
AttrDiffFactor = 1 + max(自身主属性 / 2, 自身主属性 - 对方主属性 / 2) / 10
```

**公式含义**：
- 当自身主属性 = A，对方主属性 = B：
  - 若 A > B/2：加成 = (A - B/2) / 10
  - 若 A ≤ B/2：加成 = A/2 / 10（最低保底加成）

**属性差加成示例**：

| 自身主属性(A) | 对方主属性(B) | AttrDiffFactor | 说明 |
|-------------|-------------|----------------|------|
| 1000 | 1000 | 1 + (1000-500)/10 = 1 + 50 = **51倍** | 等属性时 |
| 2000 | 1000 | 1 + (2000-500)/10 = 1 + 150 = **151倍** | 属性压制 |
| 500 | 1000 | 1 + max(250, 0)/10 = 1 + 25 = **26倍** | 被压制时 |

> 🗒️ **重要**：属性差是 SF Game 中**最核心的伤害驱动因素**。不断提升主属性是最高优先级投入。公式中的"/ 10"并非最终结果，因为武器基础伤害值本身是原始数值，整个公式结合起来才是实际最终伤害。

### 5.3 武器伤害值

🅰️ **A级**（官方帮助中心 + sfporadnik.pl）

- 武器有 **MinDmg** 和 **MaxDmg** 两个值，每次攻击从此区间随机取值
- 武器等级（与角色等级匹配）决定伤害范围
- **武器系数（WeaponFactor）** 乘以武器基础伤害：

| 职业 | 武器系数 | 说明 |
|------|---------|------|
| 法师 / 德鲁伊 / 吟游诗人 / 死灵法师 | ×4.5 | 法杖高系数补偿低甲 |
| 游侠 | ×2.5 | 弓箭系数 |
| 恶魔猎手 | ×2.5 | 弩系数 |
| 战士 / 圣骑士 | ×2 | 剑/锤系数 |
| 刺客 | ×2（双持，每轮×2次）| 双剑合计等效×4 |
| 狂战士 | ×2 | 斧，配合连击 |
| 战斗法师 | ×2 | — |

### 5.4 符文修正因子（Rune Factor）

🅲 **C级**（sf-tools 符文计算逻辑）

```
符文修正因子 = 1 + (1 - min(75, 目标抗性符文) / 100) × min(60, 己方伤害符文) / 100
```

| 参数 | 取值范围 | 说明 |
|------|---------|------|
| 伤害符文（Damage Rune）| 0~60（上限60）| 提升输出 |
| 抗性符文（Resistance Rune）| 0~75（上限75）| 降低承受伤害 |

## 6. 暴击系统

🅲 **C级**（sf-tools 暴击计算逆向）

### 6.1 暴击率公式

```
暴击率 = min(50%, 职业基础暴击率 + 幸运(LCK) × 2.5 / 目标等级 / 100)
```

**参数说明**：
- **职业基础暴击率**：大部分职业为 0（熊形态德鲁伊 +10%，恶犬加成时死灵 +10%）
- **幸运 × 2.5**：幸运每点贡献 2.5 基础暴击点数
- **/ 目标等级 / 100**：换算为百分比，并被目标等级压制
- **上限 50%**：暴击率硬上限

**公式直觉**：幸运对等级差非常敏感。对同级目标效率最高；对高等级目标暴击率会显著下降。

### 6.2 暴击率示例（自身幸运 = 500）

| 目标等级 | 计算结果 |
|---------|---------|
| 等级 10 | min(50%, 500×2.5/10/100) = min(50%, 125%) = **50%** |
| 等级 30 | min(50%, 500×2.5/30/100) = min(50%, 41.7%) = **41.7%** |
| 等级 50 | min(50%, 500×2.5/50/100) = min(50%, 25%) = **25%** |
| 等级 100 | min(50%, 500×2.5/100/100) = min(50%, 12.5%) = **12.5%** |

> 🗒️ 结论：幸运对同级和低级对手价值极高，对高等级对手收益骤降。竞技场中主要靠属性差胜出，幸运是辅助。

### 6.3 暴击伤害倍率

🅲 **C级**（sf-tools）

```
暴击伤害倍率 = 2.0（基础）
            + 0.05（武器暴击附魔加成，如有）
            + 0.11 × (自身竞技场等级 - 目标竞技场等级)  ← 仅竞技场战斗生效
            + 零食暴击倍率加成
```

- **基础暴击倍率 2x**：暴击造成双倍伤害
- **竞技场等级差**：荣誉排名越高，暴击倍率越强（鼓励挑战高排名）
- **德鲁伊熊形态**：暴击倍率额外 +400%（变为 6x）

## 7. 怒气（Rage）系统

🅲 **C级**（sf-tools `base.js` 怒气倍率逻辑）

### 7.1 怒气倍率公式

```
怒气倍率(RageMultiplier) = 1 + 当前回合数(CurrentRound) / 6
```

### 7.2 怒气倍率数据表

| 回合数 | 怒气倍率 | 说明 |
|--------|---------|------|
| 1 | 1.00× | 战斗开始，无加成 |
| 6 | 2.00× | 伤害翻倍 |
| 12 | 3.00× | 三倍伤害 |
| 18 | 4.00× | 四倍伤害 |
| 24 | 5.00× | 极端延长战斗 |
| 30 | 6.00× | 几乎不会到这里 |

### 7.3 设计意义

🅳 **D级**（推测）

- 避免两个高防御职业（如圣骑士 vs 圣骑士）无限拖延
- 确保战斗**必然在有限回合内结束**
- 营造紧张感：后期每回合威胁感知递增
- 对**高血量职业（圣骑士）略有劣势**：多回合高怒气时更难撑住

## 8. 回合制战斗流程

🅱️ **B级**（攻略站归纳）+ 🅲 **C级**（sf-tools 流程验证）

### 8.1 战斗初始化

```
战斗开始时执行（仅一次）：
1. 计算双方最终HP（公式见§3）
2. 触发职业战前特效：
   - 战斗法师：奥术彗星（Arcane Comet）
   - 圣骑士：初始姿态为"普通姿态"
   - 吟游诗人：旋律计时器归零
   - 德鲁伊：鹰形态/熊形态计时器归零
3. 判定先攻（Attack Order）
```

### 8.2 先攻判定

🅱️ **B级**（社区整理）

- 竞技场：**荣誉值较高的玩家先攻**（🅰️ A级）
- 地下城：通常**玩家先攻**（具体可能有NPC等级修正）
- 同等荣誉：随机决定

### 8.3 单回合执行流程

```
每回合执行：

Step 1: 攻击方选定攻击（单次/双持双次/连击）
        ↓
Step 2: 防御方判定特殊防御机制
        ├── 格挡判定（战士/圣骑士）
        │   成功 → 伤害取消，可能触发圣骑士姿态切换
        ├── 闪避判定（游侠/德鲁伊/刺客）
        │   成功 → 伤害取消，可能触发德鲁伊熊形态
        └── 均无 → 进入伤害计算
        ↓
Step 3: 伤害计算（见§5）
        ├── 计算属性差加成因子
        ├── 计算护甲减伤
        ├── 暴击判定（见§6）
        └── 应用怒气倍率（见§7）
        ↓
Step 4: 扣减防御方 HP
        ↓
Step 5: 检测 HP ≤ 0
        ├── 是 → 进入死亡/复活判定
        │   ├── 恶魔猎手：44%概率复活（第1次）
        │   └── 均无 → 战斗结束
        └── 否 → 交换攻守双方，进入下一回合
        ↓
Step 6: 更新怒气倍率（round += 1）
        ↓
Step 7: 触发持续性效果
        ├── 吟游诗人：旋律触发判定（每4回合一次）
        ├── 死灵法师：召唤物持续时间递减
        └── 德鲁伊：形态持续时间递减
```

### 8.4 战斗结束条件

| 条件 | 结果 |
|------|------|
| 防御方 HP ≤ 0（攻击方成功击杀）| 攻击方胜利 |
| 复活判定失败（恶魔猎手死亡未复活）| 当前攻击方胜利 |
| 怒气超高（>30回合）| 必然有一方血量先耗尽 |

| 参数 | 数值 |
|------|------|

| **对法师** | 闪避对法师无效 |

### 9.4 刺客（Assassin）— 双持

| 参数 | 数值 |
|------|------|
| **双持效果** | 每回合攻击**两次** |
| **每次伤害系数** | 0.625（两次合计 = 1.25，高于单次）|

> 🗒️ 刺客实质上每回合有两次造成伤害的机会，且每次伤害单独判断防御，实际DPS高但单次伤害不大。

| 参数 | 数值 |

### 9.7 恶魔猎手（Demon Hunter）— 复活

| 参数 | 数值 |
|------|------|
| **复活触发** | HP 降为 0 时 |
| **第1次复活概率** | 44% |
| **复活后 HP** | 90% 最大 HP |
| **复活后概率** | 每次复活后概率 -11%（第2次：33%，第3次：22%...）|

```
第N次复活概率 = 44% - (N-1) × 11%
第N次复活HP = 最大HP × (90% - (N-1) × 10%)
```

### 11.2 关键平衡设计规律

🅳 **D级**（推测）

1. **穿甲 vs 高甲**：法师（穿甲）天然克制高护甲职业（战士/圣骑士），但自身血厚
2. **格挡/闪避 vs 法师**：格挡/闪避对法师无效，形成明确克制关系
3. **血量 vs 输出**：法师 ×2 血量 vs ×4.5 武器系数；战士 ×5 血量 vs ×2 武器系数
4. **单体爆发 vs 持续输出**：狂战士（连击爆发）vs 吟游诗人（稳定加成）
5. **怒气惩罚**：随回合增加，不利于高血量持久战职业

## 12. 复刻实现要点

🅳 **D级**（开发建议）

### 12.1 最小可实现战斗系统（MVP）

```javascript
// 战斗核心类（伪代码）
class BattleSimulator {
  
  // 初始化战斗双方
  constructor(attacker, defender) {
    this.attacker = attacker;
    this.defender = defender;
    this.round = 0;
  }
  
  // 计算HP
  calculateHP(character) {
    return Math.ceil(
      character.constitution
      * CLASS_LIFE_MULTIPLIER[character.class]
      * (character.level + 1)
    );
  }
  
  // 计算护甲减伤
  calculateArmorReduction(armor, attackerLevel, classMaxReduction) {
    return Math.min(classMaxReduction, armor / attackerLevel);
  }
  
  // 计算属性差加成
  calculateAttrDiffFactor(selfAttr, targetAttr) {
    const bonus = Math.max(selfAttr / 2, selfAttr - targetAttr / 2);
    return 1 + bonus / 10;
  }
  
  // 计算怒气倍率
  getRageMultiplier() {
    return 1 + this.round / 6;
  }
  
  // 单回合战斗
  doRound() {
    this.round++;
    const rage = this.getRageMultiplier();
    
    // 防御判定
    if (this.checkBlock(this.defender)) return; // 格挡成功，本回合无伤
    if (this.checkDodge(this.defender)) return; // 闪避成功，本回合无伤
    
    // 伤害计算
    const weaponDmg = this.randomWeaponDmg(this.attacker);
    const attrFactor = this.calculateAttrDiffFactor(
      this.attacker.primaryAttr, 
      this.defender.primaryAttr
    );
    const armorReduction = this.calculateArmorReduction(
      this.defender.armor,
      this.attacker.level,
      CLASS_MAX_ARMOR[this.defender.class]
    );
    
    let damage = weaponDmg 
      * CLASS_DMG_FACTOR[this.attacker.class]
      * attrFactor
      * (1 - armorReduction)
      * rage;
    
    // 暴击判定
    if (this.checkCrit(this.attacker, this.defender)) {
      damage *= 2.0; // 基础暴击2倍
    }
    
    this.defender.currentHP -= damage;
  }
  
  // 完整战斗运行
  run() {
    this.attacker.currentHP = this.calculateHP(this.attacker);
    this.defender.currentHP = this.calculateHP(this.defender);
    
    while (this.attacker.currentHP > 0 && this.defender.currentHP > 0) {
      this.doRound();
      // 交换攻守
      [this.attacker, this.defender] = [this.defender, this.attacker];
    }
    
    return this.attacker.currentHP > 0 ? 'attacker_wins' : 'defender_wins';
  }
}
```
